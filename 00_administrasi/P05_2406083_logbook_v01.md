## 2. Checklist Penilaian Pertemuan 5 (Bagian C.4)

- [x] Seluruh field tabel terisi: Nama use case, Aktor, Tujuan, Deskripsi, kolom Kegiatan dan Respon sistem, Skenario Normal, Skenario Alternative, dan Skenario Akhir.
- [x] Langkah ditulis berurutan, satu aksi per langkah, dan penomoran berlanjut dari Skenario Normal ke Skenario Alternative tanpa pengulangan nomor.
- [x] Kolom Kegiatan hanya berisi aksi aktor dan kolom Respon sistem hanya berisi tanggapan sistem.
- [x] Data yang dimasukkan dan data yang ditampilkan disebut secara eksplisit, termasuk nama field, nilai, atau status.
- [x] Relasi include ditulis sebagai langkah rujukan pada Skenario Normal dengan nama, ID, dan tabel skenario use case yang disertakan, tanpa menyalin langkahnya.
- [x] Relasi extend ditulis sebagai cabang bersyarat pada Skenario Alternative lengkap dengan condition dan extension point, serta sebagai rujukan ke tabel skenario use case tambahan.
- [x] Generalization aktor diterapkan: skenario aktor umum ditulis satu kali ditambah catatan aktor khusus yang berlaku; tidak ada tabel ganda untuk aktor khusus yang perilakunya sama.
- [x] Generalization use case diterapkan: skenario umum memuat perilaku bersama, skenario khusus memuat perilaku pembeda dan merujuk ke skenario umum.
- [x] Collaboration disebut pada keterangan tabel use case yang direalisasikannya dan tidak diberi langkah kegiatan sendiri.
- [x] Setiap tabel mempunyai Skenario Alternative dan Skenario Akhir, termasuk untuk use case yang jalurnya tampak sederhana.
- [x] Nama, ID, aktor, condition, dan extension point sama persis dengan diagram kumulatif Pertemuan 4.
- [x] Catatan pemeriksaan untuk aktor Kepala Laboratorium: aktor ini hanya mempunyai satu use case, yaitu `LAB-UC07 Lihat Laporan Peminjaman`, dan `LAB-UC07` tidak mempunyai relasi lain (berdiri sendiri).
- [x] Berkas diagram P04 tidak diubah; dokumen skenario disimpan pada folder `01_skenario` dengan nama dan versi yang benar.
